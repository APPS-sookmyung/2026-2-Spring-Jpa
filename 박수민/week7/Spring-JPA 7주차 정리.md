# 6. 주문 도메인 개발

## 1. 구현 기능

- 상품 주문, 주문 내역 조회, 주문 취소
- 개발 순서: 엔티티 → 리포지토리 → 서비스 → 테스트 → 검색

## 2. 주문 엔티티 개발

### Order 엔티티

- 주문 회원, 주문상품, 배송정보, 주문시간, 주문상태 관리
- `createOrder()` : 주문 생성 및 연관관계 설정
- `cancel()` : 주문상태 `CANCEL` 변경 및 주문상품 취소
    - 배송 완료(`COMP`) 시 취소 불가
- `getTotalPrice()` : 전체 주문상품 금액 합산

### OrderItem 엔티티

- 주문상품, 주문가격, 주문수량 관리
- `createOrderItem()` : 주문상품 생성 및 재고 감소
- `cancel()` : 취소 수량만큼 재고 복구
- `getTotalPrice()` : 주문가격 × 주문수량

## 3. 주문 리포지토리 개발

**OrderRepository**

- `save()` : `em.persist()`로 주문 저장
- `findOne()` : `em.find()`로 주문 조회
- `findAll()` : 검색 조건에 따른 주문 조회

## 4. 주문 서비스 개발

**OrderService**

### 주문 — `order()`

1. 회원 및 상품 조회
2. 배송정보 생성 (`READY`)
3. 주문상품 생성 및 재고 감소
4. 주문 엔티티 생성
5. 주문 저장 후 ID 반환

### 주문 취소 — `cancelOrder()`

- 주문 조회 후 `order.cancel()` 호출
- 주문상태 변경 및 재고 복구

### 도메인 모델 패턴

- **도메인 모델 패턴** : 엔티티에서 비즈니스 로직 처리
- **트랜잭션 스크립트 패턴** : 서비스 계층에서 비즈니스 로직 처리
- 해당 예제는 도메인 모델 패턴 사용

## 5. 주문 기능 테스트

| 테스트 | 검증 내용 |
| --- | --- |
| 상품 주문 | 주문상태 `ORDER`, 금액 및 재고 감소 확인 |
| 재고 초과 | `NotEnoughStockException` 발생 확인 |
| 주문 취소 | 주문상태 `CANCEL`, 재고 복구 확인 |

**JUnit5**

- `assertEquals(기대값, 실제값, 메시지)` : 값 비교
- `assertThrows(예외.class, () -> 실행코드)` : 예외 발생 검증

## 6. 주문 검색 기능 개발

### OrderSearch

- `memberName` : 회원 이름
- `orderStatus` : 주문상태 (`ORDER`, `CANCEL`)
- 검색 조건에 따라 동적 쿼리 생성

### 동적 쿼리 처리 방식

- **JPQL** : 문자열 조합 방식, 복잡하고 오류 발생 가능
- **JPA Criteria** : JPA 표준 방식, 코드 복잡하고 가독성 낮음
- **Querydsl** : 동적 쿼리 문제 해결을 위한 대안
