# 앱스 JPA 스터디 강의 내용 요약

## 2. 도메인 분석 설계

이번 강의에서는 회원, 상품, 주문 기능을 가진 애플리케이션을 예시로 도메인 모델을 설계하고, JPA를 이용해 엔티티 간의 연관관계를 매핑하는 방법을 학습하였다. 또한 값 타입의 활용과 엔티티 설계 시 고려해야 할 주요 사항을 다루었다.

### 2-1. 요구사항 분석

애플리케이션을 개발하기 전에 필요한 기능을 정의하고, 이를 바탕으로 도메인 모델을 구성한다.

- 회원 관리: 회원 등록 및 조회 기능을 구현한다.
- 상품 관리: 상품 등록, 수정, 조회 기능을 제공하며 재고를 관리한다.
- 주문 관리: 상품 주문, 주문 내역 조회, 주문 취소 기능을 구현한다.
- 기타 기능: 상품을 도서, 음반, 영화로 구분하고 카테고리와 배송 정보를 관리한다.

### 2-2. 도메인 모델 설계

요구사항을 바탕으로 애플리케이션에서 사용할 엔티티와 각 엔티티의 역할을 정의한다.

- Member: 회원의 이름, 주소, 주문 목록 등을 관리한다. 주소는 별도의 엔티티가 아닌 값 타입으로 설계한다.
- Order: 주문한 회원, 주문 날짜, 주문 상태, 배송 정보 등을 관리한다. 주문 상태는 `ORDER`, `CANCEL` 등의 Enum으로 정의한다.
- OrderItem: 주문과 상품을 연결하며 주문 가격과 수량을 저장한다. 다대다 관계를 중간 엔티티로 분리하여 관리한다.
- Item: 상품명, 가격, 재고 수량 등의 공통 정보를 관리한다. Book, Album, Movie가 Item을 상속하며, `SINGLE_TABLE` 전략을 통해 하나의 테이블에 저장한다.
- Delivery: 주문별 배송 정보와 배송 상태를 관리한다.
- Category: 상품을 분류하고 부모·자식 관계를 통해 계층형 카테고리를 구성한다.

### 2-3. 엔티티 연관관계 매핑

JPA에서는 엔티티 간 관계를 설정할 때 외래 키의 위치를 고려하여 연관관계의 주인을 결정한다. 일반적으로 외래 키를 관리하는 엔티티가 연관관계의 주인이 된다.

- 회원과 주문: 1:N 관계이며, 외래 키를 가진 Order가 연관관계의 주인이 된다.
- 주문과 주문상품: 1:N 관계로, OrderItem이 외래 키를 관리한다.
- 주문상품과 상품: N:1 관계이며, 여러 주문상품이 하나의 상품을 참조할 수 있다.
- 주문과 배송: 1:1 관계로 매핑하며, Order에서 배송 정보를 참조한다.
- 상품과 카테고리: N:M 관계로 표현할 수 있지만, 실무에서는 중간 엔티티를 두어 관계를 분리하는 것이 권장된다.

양방향 연관관계에서는 객체 간 참조가 일치하도록 관리해야 한다. 이를 위해 연관관계 편의 메서드를 작성하여 양쪽 객체의 관계를 한 번에 설정할 수 있다.

또한 `cascade = CascadeType.ALL`을 적용하면 부모 엔티티의 영속성 작업을 관련 자식 엔티티에 전파할 수 있다.

### 2-4. 값 타입 활용

JPA에서는 독립적인 식별자가 필요하지 않은 데이터를 값 타입으로 정의하여 사용할 수 있다.

- @Embeddable: 여러 속성을 하나의 값 타입으로 정의한다.
- @Embedded: 정의한 값 타입을 엔티티 내부에서 사용한다.
- Address는 도시, 도로명, 우편번호 등의 속성을 가지며, 별도 엔티티가 아닌 값 타입으로 관리한다.
- 값 타입의 속성은 해당 엔티티 테이블의 컬럼으로 저장된다.
- 값 타입은 데이터의 일관성을 유지하기 위해 생성 이후 변경할 수 없도록 불변 객체로 설계하는 것이 권장된다.

### 2-5. 엔티티 설계 시 주의사항

1\. Setter 사용 최소화

- Setter를 무분별하게 사용하면 데이터 변경 지점을 추적하기 어려워진다.
- 단순한 Setter 대신 변경 목적이 드러나는 비즈니스 메서드를 작성하는 것이 좋다.
- Getter는 데이터 조회를 위해 사용할 수 있다.

2\. 지연 로딩(LAZY) 활용

- 연관된 엔티티를 필요한 시점에 조회하도록 지연 로딩을 설정한다.
- 즉시 로딩(EAGER)은 예상하지 못한 SQL 실행이나 N+1 문제를 발생시킬 수 있다.
- `@ManyToOne`, `@OneToOne`은 기본적으로 EAGER이므로 `FetchType.LAZY`를 명시하는 것이 좋다.
- 연관 데이터를 한 번에 조회해야 할 경우 Fetch Join이나 EntityGraph를 활용할 수 있다.

3\. 컬렉션 초기화

- 엔티티의 컬렉션 필드는 `new ArrayList<>()` 등을 이용하여 선언 시점에 초기화한다.
- 이를 통해 NullPointerException 발생 가능성을 줄일 수 있다.
- Hibernate는 영속 상태의 컬렉션을 자체 관리 컬렉션으로 변경하므로 컬렉션 객체 자체를 임의로 교체하지 않는 것이 좋다.

### 2-6. 정리

이번 강의에서는 요구사항을 분석하여 엔티티를 정의하고, 각 엔티티 사이의 관계를 JPA로 매핑하는 과정을 학습하였다.

특히 외래 키를 기준으로 연관관계의 주인을 결정하는 방법, 다대다 관계를 중간 엔티티로 분리하는 방식, 값 타입을 활용한 데이터 설계가 중요하다.

또한 엔티티의 변경을 명확하게 관리하고, 지연 로딩과 컬렉션 초기화를 적절히 활용하는 것이 유지보수성과 성능 측면에서 중요하다는 점을 학습하였다.
