# JPA 스터디 강의 내용 요약

## 3. 애플리케이션 구현 준비

이번 강의에서는 앞서 설계한 도메인 모델을 바탕으로 실제 애플리케이션을 구현하기 위한 요구사항과 전체 구조를 정리하였다. 특히 애플리케이션을 계층별로 분리하여 각 계층의 역할을 명확히 하고, 효율적인 개발 순서를 설정하는 방법을 학습하였다.

### 3-1. 구현 요구사항

애플리케이션의 핵심 기능을 회원, 상품, 주문 관리로 구분하여 구현한다.

- 회원 관리: 회원 등록 및 조회 기능을 제공한다.
- 상품 관리: 상품 등록, 수정, 조회 기능을 구현한다.
- 주문 관리: 상품 주문, 주문 내역 조회, 주문 취소 기능을 구현한다.
- 구현 범위 제한: 예제의 복잡도를 줄이기 위해 로그인, 권한 관리, 입력값 검증, 예외 처리 등은 제외한다.
- 상품은 도서(Book)만 사용하며 카테고리와 배송 정보 기능도 구현 대상에서 제외한다.

### 3-2. 애플리케이션 아키텍처

애플리케이션은 역할에 따라 계층을 분리하는 계층형 아키텍처(Layered Architecture) 를 적용한다.

- Controller(Web): 사용자의 HTTP 요청을 받아 처리하고 결과를 반환하는 웹 계층이다.
- Service: 회원 등록이나 상품 주문과 같은 비즈니스 로직을 수행하고 트랜잭션을 관리한다.
- Repository: JPA의 `EntityManager`를 이용해 데이터베이스 저장 및 조회 작업을 담당한다.
- Domain: Member, Order, Item 등 핵심 엔티티를 관리하며 여러 계층에서 공통으로 사용한다.

각 계층의 책임을 구분하면 코드의 유지보수성이 높아지고 기능별 테스트와 수정이 용이해진다.

### 3-3. 패키지 구조

프로젝트는 기능과 역할에 따라 패키지를 분리하여 구성한다.

- `domain`: 엔티티 및 도메인 모델 관리
- `repository`: 데이터베이스 접근 로직 구현
- `service`: 비즈니스 로직과 트랜잭션 처리
- `web`: 컨트롤러 및 웹 요청 처리
- `exception`: 애플리케이션의 예외 관련 코드 관리

이러한 구조는 코드의 역할을 명확하게 구분하고, 기능을 추가하거나 수정할 때 관리하기 편리하다는 장점이 있다.

### 3-4. 개발 순서

애플리케이션은 핵심 기능을 먼저 구현한 후 웹 계층을 연결하는 방식으로 개발한다.

1. Repository 구현: 엔티티의 저장 및 조회 등 데이터 접근 기능을 작성한다.
2. Service 구현: Repository를 활용하여 비즈니스 로직과 트랜잭션을 구성한다.
3. 테스트 진행: 작성한 기능이 정상적으로 동작하는지 확인한다.
4. 웹 계층 구현: 검증된 기능을 Controller와 연결하여 사용자 요청을 처리한다.

### 3-5. 정리

이번 강의에서는 실제 기능 구현에 앞서 요구사항을 구체화하고, 계층형 아키텍처를 기반으로 프로젝트 구조를 설계하는 과정을 학습하였다.

핵심은 Controller, Service, Repository, Domain의 역할을 구분하고, 데이터 접근 및 비즈니스 로직을 먼저 구현한 후 테스트를 거쳐 웹 기능을 연결하는 것이다. 이를 통해 각 계층의 책임을 명확히 하고 유지보수와 확장이 용이한 애플리케이션을 개발할 수 있다.
