# JPA 기초 18. JPQL

### JPQL

JPA Query Language

- SQL 쿼리와 유사
- 테이블 대신 엔티티 이름, 속성 사용

### 기본 사용법

JPQL 기본 구조 : select 별칭 from 엔티티명 별칭 …

ex. select r from Review r

쿼리 생성 : TypedQuery<T> EntityManager#createQuery(String ql, Class<T> resultClass)

### 검색 조건 지정

1. where + and, or, 괄호
2. 파라미터
    - 이름 사용 : query.setParameter(”hotelId”, “H-001”)
    - 인덱스 기반 : query.setParameter(0, “H-001”)

### 주의

아래 경우엔 JPQL 말고 일반 쿼리 사용 고려

- 여러 테이블 조인
- DBMS에 특화된 쿼리 필요
- 서브 쿼리 필요
- 통계, 대량 데이터 조회/처리

# JPA 기초 19. Criteria 소개

### Criteria

코드로 쿼리를 구성하는 API : JPQL 대신 자바 코드 사용

### 기본 사용법

1. CriteriaBuilder 생성
2. CreateQuery 생성, 파라미터는 쿼리 결과 타입
3. CQ#from 으로 from 절 엔티티 지정, Root 타입 이용해서 엔티티 속성 접근
4. CQ#select 로 select 대상 지정
5. CQ#where 로 조건 지정, CB를 이용해서 Predicate 생성
6. CQ#orderBy 로 정렬 순서 지정, CB를 이용해서 Order 생성
7. CQ를 이용해서 TypedQuery 생성

### 검색 조건 지정

CQ#where 메서드에 검색 조건 전달

- 검색 조건은 CB를 이용해서 생성
- 검색 조건에 사용할 엔티티 속성은 Root#get() 메서드로 구함

조합 : CB#and, CB#or로 조건 조합

### 정렬 순서

CQ#orderBy로 정렬 지정

CB#asc(), CB#desc()로 정렬 정보(Order) 생성

- 정렬 대상 속성은 Root#get()으로 구함
- 한 개 이상 정렬 지정 가능

### Root#get()과 지네릭 타입

<Y> Path<Y> get(String attributeName)

- in() 조건을 생성할 때 타입 파라미터 지정하면 유용

### Criteria 사용 이점

동적인 검색 조건 지정 가능

### 주의

아래 경우엔 Criteria 말고 일반 쿼리 사용 고려

- 여러 테이블 조인
- DBMS에 특화된 쿼리 필요
- 서브 쿼리 필요
- 통계, 대량 데이터 조회/처리

연관 + 쿼리를 사용하고 싶다면 N+1 문제, fetch 조인 추가 학습

→ 단순하지 않는 목록 조회/상세 조회는 그냥 SQL 쓰기(CQRS)

# JPA 기초 20. 기타 특징

### AttributeConverter

매핑을 지원하지 않는 자바 타입과 DB 타입 간 변환 처리

ex. boolean 타입과 char(1) 타입 간 변환

### @Formula

SQL을 이용한 속성 매핑

- 조회에서만 매핑 처리
- 하이버네이트 제공 기능
- 주로 DB 함수 호출, 서브 쿼리 결과를 매핑

### @DynamicUpdate/@DynamicInsert

@DynamicUpdate : 변경된 칼럼만 UPDATE 쿼리에 포함

@DynamicInsert : null이 아닌 칼럼만 INSERT 쿼리에 포함

- 기본값을 사용할 수 있음 → null을 지정해야 할 경우 사용X

### @Immutable

변경 추적 대상에서 제외 처리

- 변경 추적 위한 메모리 사용 감소
- 주로 조회 목적으로만 사용되는 엔티티 매핑에 사용

### @Subselect

select 결과를 엔티티로 매핑

수정 대상이 아니므로 @Immutable과 함께 사용

# JPA 기초 22. 메서드 작성 규칙

### DB 연동 코드 구현 방법

1. Repository 인터페이스를 상속
2. 정해진 규칙에 따라 메서드를 추가

### 식별자로 엔티티 조회

findById : T findById(ID id), Optional<T> findById(ID id)

### 엔티티 삭제

delete : void delete(T entity), void deleteById(ID id)

- 삭제할 대상 존재X → 익셉션 발생

### save() 동작 방식

새 엔티티면 EntityManager#persist() 실행

새 엔티티가 아니면 EntityManager#merge() 실행

새 엔티티인지 판단하는 기준

- Persistable을 구현한 엔티티 : isNew()로 판단
- @Version 속성이 있는 경우 : 버전 값이 null이면 새 엔티티로 판단
- 식별자가 참조 타입 : 식별자가 null이면 새 엔티티로 판단
- 식별자가 숫자 타입 : 0이면 새 엔티티로 판단

### 특정 조건으로 찾기

findBy프로퍼티(값) : 프로퍼티가 특정 값인 대상

조건 비교

findAll() : 모두 조회

### 주의

findBy 메서드를 남용하지 말 것

검색 조건이 단순하지 않으면 @Query, SQL, 스펙/QueryDSL 사용
