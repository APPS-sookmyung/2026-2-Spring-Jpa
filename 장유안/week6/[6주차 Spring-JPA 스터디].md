##### 엔티티 설계 시 주의점



###### 엔티티에는 가급적 Setter를 사용하지 말자.

* Setter를 모두 열어두면 데이터 변경 지점이 많아져 유지보수가 어려워진다.
* 필요한 경우 변경 목적이 명확한 비즈니스 메서드를 사용하는 것이 좋다.
* 강의 예제에서는 단순화를 위해 Setter를 사용하며, 추후 리팩토링으로 제거한다.



###### 모든 연관관계는 지연 로딩(LAZY)으로 설정한다.

* EAGER(즉시 로딩)는 실행되는 SQL을 예측하기 어렵고, JPQL 사용 시 N+1 문제가 발생하기 쉽다.
* LAZY(지연 로딩)는 연관된 엔티티가 실제 필요한 시점에 조회되도록 한다.
* 연관 엔티티를 함께 조회해야 한다면 fetch join 또는 엔티티 그래프를 사용한다.
* @ManyToOne, @OneToOne은 기본이 즉시 로딩이므로 명시적으로 LAZY를 설정해야 한다.



###### 컬렉션은 필드에서 바로 초기화한다.

* null 문제를 방지하고 안전하게 사용할 수 있다.
* Hibernate는 엔티티를 영속화할 때 컬렉션을 자체 관리 컬렉션으로 변경한다.
* 따라서 컬렉션을 임의로 다시 생성하지 않고 필드에서 초기화하는 것이 좋다.
private List<Order> orders = new ArrayList<>();

###### 테이블 및 컬럼명 생성 전략

* Spring Boot는 Hibernate의 이름 생성 전략을 사용하여 엔티티의 이름을 데이터베이스 테이블 및 컬럼명으로 변환한다.

|변환 규칙|예시|
|-|-|
|카멜 케이스 → 언더스코어|memberPoint → member\_point|
|점(.) → 언더스코어(\_)|a.b → a\_b|
|대문자 → 소문자|Member → member|

* ImplicitNamingStrategy: 테이블명이나 컬럼명을 명시하지 않았을 때 논리명을 생성한다.
* PhysicalNamingStrategy: 논리명을 실제 DB에서 사용하는 물리명으로 변환한다.
