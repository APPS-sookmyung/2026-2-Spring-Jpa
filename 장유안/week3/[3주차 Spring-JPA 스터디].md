\[3주차 Spring-JPA 스터디]

#### 값 콜렉션 set 매핑

* 단순 값을 set로 표현하는 모델
* 저장, 조회(lazy, eager), 수정(add(), remove()), 새로 할당(clear())
* @ElementCollection과 @CollectionTable

#### 값 콜렉터 List 매핑

* 단순 값을 List로 보관하는 모델
* 저장(insert into), 조회(lazy, eager)
* 새로 할당 (delete from → insert into)
* 위에서 @OrderColumn추가

#### Map

* 단순 값을 Map로 보관하는 모델
* 추가(delete from 문서명), 수정(update 문서명), 삭제(insert into 문서)
* @MapKeyColumn

#### 값 콜렉션 주의사항

* JPA를 이용하여 모든것을 처리하려고 하지 말기
* 명령모델(상태 변경)과 조회모델을 구분하여 코드 작성하

#### 영속 컨텍스트\&라이프사이클

* **영속(Persistent) 엔티티/객체**

  * DB 데이터에 매핑되는 메모리상의 객체
* **영속 컨텍스트**

  * 일종의 메모리 저장소
  * EntityManager가 관리할 엔티티 객체 보관
  * 엔티티타입, 식별자 → 엔티티 객체
* **EntityManager.close()**

  * 영속 컨텍스트 제거
* 동일 식별자 -> 동일 객체 (영속 컨텍스트에 보관된 객체 조회)
* 연속 컨텍스트와 변경 추적

  * 조회(find)나 persist()를 통해 영속 컨텍스트에 저장된 객체는 관리대상이 된다.
  * 분리됨 상태는 변경을 추적하지 않음

#### 엔티티 연관 매핑 시작 전

* 엔티티와 엔티티간의 연결

  * 엔티티가 다른 엔티티를 필드/프로퍼티로 참고
  * **1-1: 참조키 방식 — 단 방향**, 양 방향
  * **1-1**: 키 공유 방식 — 단 방향, 양 방향
  * **N-1: 단 방향**
  * **1-N: 콜렉션 단 방향**
  * **N-1/1-N**: 양 방향
  * **M-N**: 단 방향 / 양 방향
* Embeddable 매핑이 가능하다면 그것을 사용하기 엔티티 연관 매핑은 진짜 필요할 떄만 사용하기

#### 영속성 전파 \& 연관 고려사항

* 영속성 전파: 연관된 엔티티에 영속 상태를 전파

  * 주의:사용하지 말것
  * 예. 저장할 때 연관된 엔티티 함꼐저장(팀 저장할 때, 선수도 저장)
* 연관 고려 사항

  * 연관 대신에 ID 값으로 참조 고려
  * 객체 탐색이 쉽다고 연관 없이 쓰지 말기
  * 조회는 전용 쿼리나 구현 사용 고려 (CQRS)
  * 엔티티가 아닌 밸류인지 확인

    * 1-1, 1-N 관계에서 특히
  * **1-N 보다는 N-1**
  * 양방향 X
