### \[5주차 Spring-JPA 스터디]



도메인 모델과 테이블 설계
엔티티 간 관계
---

* 회원 ↔ 주문: 일대다(1:N) 관계
* 주문 ↔ 상품: 다대다(N:M) 관계이지만, 주문상품(OrderItem) 엔티티를 추가해 일대다·다대일 관계로 분리
* 주문 ↔ 배송: 일대일(1:1) 관계
* 상품 ↔ 카테고리: 다대다(N:M) 관계
상품 상속 구조
* Item을 공통 부모 클래스로 사용
* Book, Album, Movie가 상속
* 상품의 공통 속성을 관리하면서 종류별 속성을 구분



##### 주요 엔티티 분석

|엔티티|주요 속성 및 역할|
|-|-|
|Member|이름, 주소, 주문 목록|
|Order|회원, 주문상품, 배송, 주문 날짜, 주문 상태|
|OrderItem|주문 상품, 주문 가격, 수량|
|Item|상품명, 가격, 재고수량|
|Delivery|배송 정보, 배송 상태|
|Category|상품 분류, 부모·자식 카테고리|
|Address|회원과 배송에서 사용하는 임베디드 값 타입|



##### 테이블 설계

* Address: 임베디드 타입이므로 회원 및 배송 테이블에 주소 컬럼이 포함
* Item: 도서, 음반, 영화를 하나의 테이블에 저장하고 DTYPE 컬럼으로 구분
* Orders: ORDER는 SQL 예약어와 충돌할 수 있어 ORDERS를 사용
* 테이블 및 컬럼명: 대문자 또는 소문자와 언더스코어(\_)를 조합



###### 연관관계 매핑


회원 ↔ 주문	
주문 ↔ 주문상품	
주문상품 → 상품	
주문 ↔ 배송	



* 연관관계의 주인은 외래 키를 관리하는 엔티티를 의미
* 실무에서는 @ManyToMany 사용을 지양



##### 엔티티 설계 시 Getter, Setter



* Getter: 데이터 조회가 많으므로 가급적 열어둘 것
* Setter: 데이터를 변경하므로 꼭 필요한 경우에만 사용
