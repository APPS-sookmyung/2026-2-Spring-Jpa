## 1. 요구사항 분석

- **회원:** 등록, 조회
- **상품:** 등록, 수정, 조회 (상품 종류는 도서·음반·영화)
- **주문:** 상품 주문, 주문 내역 조회, 주문 취소
- **기타:** 상품 재고 관리, 카테고리 분류, 배송 정보 입력

## 2. 도메인 모델과 테이블 설계

| 엔티티 | 관계 | 비고 |
| --- | --- | --- |
| `Member` ↔ `Order` | 1:N | 외래 키는 `ORDERS.MEMBER_ID` |
| `Order` ↔ `OrderItem` | 1:N | 주문 하나에 여러 상품 |
| `OrderItem` ↔ `Item` | N:1 | 주문 시점의 가격·수량 저장 |
| `Order` ↔ `Delivery` | 1:1 | 외래 키는 `ORDERS.DELIVERY_ID` |
| `Category` ↔ `Item` | N:M | 실습용, 실무에서는 사용 지양 |
| `Item` ← `Book`·`Album`·`Movie` | 상속 | 싱글 테이블 전략 |

- `ORDER`는 SQL 예약어(`order by`)라서 테이블 이름을 `ORDERS`로 지정한다.
- **연관관계의 주인은 외래 키가 있는 쪽**으로 정한다. 1:N에서는 항상 N 쪽이 외래 키를 가진다.
- 1:1은 어느 쪽에 외래 키를 둬도 되지만, 더 자주 조회하는 `Order`에 둔다.

## 3. 엔티티 클래스 개발

### 회원과 값 타입

```java
@Entity
@Getter
public class Member {
    @Id @GeneratedValue
    @Column(name = "member_id")
    private Long id;

    private String name;

    @Embedded
    private Address address;

    @OneToMany(mappedBy = "member")
    private List<Order> orders = new ArrayList<>();
}

@Embeddable
@Getter
public class Address {
    private String city;
    private String street;
    private String zipcode;

    protected Address() {}  // JPA 스펙상 기본 생성자 필요

    public Address(String city, String street, String zipcode) {
        this.city = city;
        this.street = street;
        this.zipcode = zipcode;
    }
}
```

값 타입은 **변경 불가능**하게 만든다. Setter를 두지 않고 생성자로만 값을 넣는다.

### 주문

```java
@Entity
@Table(name = "orders")
@Getter
public class Order {
    @Id @GeneratedValue
    @Column(name = "order_id")
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "member_id")
    private Member member;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL)
    private List<OrderItem> orderItems = new ArrayList<>();

    @OneToOne(fetch = FetchType.LAZY, cascade = CascadeType.ALL)
    @JoinColumn(name = "delivery_id")
    private Delivery delivery;

    private LocalDateTime orderDate;

    @Enumerated(EnumType.STRING)
    private OrderStatus status;  // ORDER, CANCEL

    // 연관관계 편의 메서드
    public void setMember(Member member) {
        this.member = member;
        member.getOrders().add(this);
    }

    public void addOrderItem(OrderItem orderItem) {
        orderItems.add(orderItem);
        orderItem.setOrder(this);
    }

    public void setDelivery(Delivery delivery) {
        this.delivery = delivery;
        delivery.setOrder(this);
    }
}
```

`OrderItem`은 `Item`, `Order`와 `@ManyToOne(fetch = LAZY)`로 연결되고 `orderPrice`, `count`를 가진다.  
`Delivery`는 `@OneToOne(mappedBy = "delivery")`로 `Order`를 참조하고 `Address`, `DeliveryStatus`(READY, COMP)를 가진다.

### 상품 상속 구조

```java
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "dtype")
@Getter
public abstract class Item {
    @Id @GeneratedValue
    @Column(name = "item_id")
    private Long id;

    private String name;
    private int price;
    private int stockQuantity;
}

@Entity
@DiscriminatorValue("B")
public class Book extends Item {
    private String author;
    private String isbn;
}
```

`Album`(`"A"`, artist·etc)과 `Movie`(`"M"`, director·actor)도 같은 방식으로 만든다.

| 상속 전략 | 특징 |
| --- | --- |
| `SINGLE_TABLE` | 한 테이블에 모든 컬럼, `dtype`으로 구분. 조회가 빠르고 단순 |
| `JOINED` | 부모·자식 테이블 분리 후 조인. 정규화에 유리 |
| `TABLE_PER_CLASS` | 자식마다 테이블. 보통 권장하지 않음 |

### 카테고리

```java
@ManyToMany
@JoinTable(name = "category_item",
        joinColumns = @JoinColumn(name = "category_id"),
        inverseJoinColumns = @JoinColumn(name = "item_id"))
private List<Item> items = new ArrayList<>();

@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "parent_id")
private Category parent;

@OneToMany(mappedBy = "parent")
private List<Category> child = new ArrayList<>();
```

`@ManyToMany`는 중간 테이블에 컬럼을 추가할 수 없어서 실무에서는 중간 엔티티(`CategoryItem`)를 만들어 `@ManyToOne` 두 개로 풀어낸다.

## 4. 엔티티 설계 시 주의점

1. **Setter는 가급적 쓰지 않는다.** 어디서 값이 바뀌는지 추적하기 어려워진다. 변경은 비즈니스 메서드로 한다.
2. **모든 연관관계는 지연 로딩(LAZY)으로 설정한다.** `@ManyToOne`, `@OneToOne`은 기본값이 EAGER라서 직접 바꿔줘야 한다. EAGER는 예측하기 어려운 SQL과 JPQL의 N+1 문제를 일으킨다. 함께 조회해야 하면 fetch join을 쓴다.
3. **컬렉션은 필드에서 바로 초기화한다.** null 문제를 막을 수 있다. 하이버네이트가 영속화할 때 컬렉션을 내장 컬렉션으로 바꾸기 때문에, 이후에 컬렉션 객체 자체를 바꾸지 않는다.
4. **테이블·컬럼명:** 스프링 부트 기본 설정은 카멜 케이스를 스네이크 케이스로 바꾼다 (`orderDate` → `order_date`).
5. **cascade:** `Order`를 저장하면 `OrderItem`과 `Delivery`도 함께 저장된다. 생명주기를 같이하는 경우에만 쓴다.
6. **연관관계 편의 메서드:** 양방향 관계는 양쪽 값을 한 번에 세팅하는 메서드를 둔다. 위치는 주로 제어하는 쪽이다.
