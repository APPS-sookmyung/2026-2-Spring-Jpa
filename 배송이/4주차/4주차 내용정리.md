## 1. JPQL과 Criteria

**JPQL**은 SQL과 비슷하지만 테이블이 아닌 **엔티티와 필드**를 대상으로 조회한다.

```java
TypedQuery<Review> query = em.createQuery("select r from Review r where r.hotelId = :hotelId", Review.class);
query.setParameter("hotelId", "H-001");
```

**Criteria**는 문자열 대신 자바 코드로 쿼리를 만드는 방식이다. `CriteriaBuilder`로 조건을 만들고, `CriteriaQuery`에서 조회 대상·조건·정렬을 설정한다. 조건을 동적으로 조합할 때 유용하지만 코드가 길어질 수 있다.

복잡한 조인이나 통계 조회처럼 SQL 제어가 중요한 작업은 별도 조회 쿼리를 고려한다.

## 2. JPA의 추가 매핑 기능

| 기능 | 용도 |
| --- | --- |
| `AttributeConverter` | 자바 타입과 DB 저장 타입 간 변환 |
| `@Formula` | SQL 계산 결과를 읽기 전용 속성으로 매핑 |
| `@DynamicUpdate` | 변경된 컬럼 위주로 UPDATE 생성 |
| `@DynamicInsert` | null이 아닌 컬럼 위주로 INSERT 생성 |
| `@Immutable` | 엔티티를 변경 불가능한 조회용으로 취급 |
| `@Subselect` | SELECT 결과를 엔티티로 매핑 |

`@Formula`, `@Immutable`, `@Subselect` 등은 Hibernate 전용 기능이다.

## 3. Spring Data JPA Repository

리포지토리 인터페이스를 정의하면 기본적인 저장·조회·삭제 기능을 편리하게 사용할 수 있다.

- `save()` : 새 엔티티는 `persist`, 기존 엔티티는 `merge` 방식으로 처리
- `findById()` : 식별자로 조회하며 보통 `Optional<T>` 반환
- `delete()` / `deleteById()` : 엔티티 삭제
- `findBy...()` : 메서드 이름으로 간단한 조회 조건 표현

단, 복잡한 검색을 메서드 이름만으로 표현하면 가독성이 떨어진다.

## 4. 정렬·페이징·직접 쿼리

- **정렬:** `OrderBy` 키워드 또는 `Sort` 사용
- **페이징:** `Pageable`, `PageRequest`로 요청하고 `Page<T>`로 결과 및 페이지 정보 확인
- **`@Query`:** 메서드 이름 대신 JPQL을 직접 작성

## 5. Specification

`Specification`은 Criteria 기반 검색 조건을 재사용하고 조합하기 위한 기능이다. 람다식으로 조건을 정의하고 `and()`·`or()`로 연결하면 선택적인 필터 구현이 쉬워진다.

## 마무리

Spring Data JPA는 반복적인 데이터 접근 코드를 줄여 준다. 다만 모든 조회를 리포지토리 메서드로 해결하기보다, **단순 CRUD와 복잡한 조회를 구분해 적절한 쿼리 방식을 선택하는 것**이 중요하다.
