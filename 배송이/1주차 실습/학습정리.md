# 1주차 실습 - Spring JPA 프로젝트 환경설정

이번 주에는 Spring Boot와 JPA를 함께 사용하는 프로젝트의 기본 환경을 구축하고, 가장 단순한 형태의 웹 요청 처리와 JPA 엔티티 저장·조회 흐름을 직접 구현해보았다. 먼저 `build.gradle`을 통해 프로젝트의 뼈대를 잡았는데, Spring Boot 3.4.4와 Java 17을 기준으로 spring-boot-starter-data-jpa, spring-boot-starter-thymeleaf, spring-boot-starter-web, spring-boot-starter-validation 등의 의존성을 추가했다. 특히 Lombok을 compileOnly와 annotationProcessor 양쪽에 모두 등록해야 어노테이션 기반의 getter/setter 자동 생성이 정상적으로 컴파일 단계에서 적용된다는 점을 확인했고, 테스트 실행을 위해 spring-boot-starter-test와 junit-platform-launcher를 추가한 뒤 `useJUnitPlatform()`으로 JUnit5 기반 테스트가 돌아가도록 설정했다.

다음으로는 Controller와 View 템플릿을 연결하는 가장 기본적인 흐름을 익혔다. `HelloController`에서 `@GetMapping("hello")`로 요청을 받아 `Model`에 데이터를 담아 `hello` 뷰로 넘기면, `templates/hello.html`의 Thymeleaf 문법(`th:text`)이 서버에서 전달된 값을 렌더링하는 구조를 실습했다. 이 과정에서 `static/index.html`처럼 정적 리소스는 별도의 템플릿 엔진 처리 없이 그대로 반환되는 반면, `templates` 아래의 파일은 Thymeleaf 엔진을 거쳐 동적으로 데이터가 바인딩된다는 정적 리소스와 템플릿의 차이를 이해할 수 있었다.

JPA 부분에서는 `Member` 클래스에 `@Entity`, `@Id`, `@GeneratedValue`를 붙여 데이터베이스 테이블과 매핑되는 엔티티를 정의했다. 이어서 `MemberRepository`를 직접 구현하면서 스프링 데이터 JPA의 `JpaRepository`를 상속받는 방식이 아니라, `EntityManager`를 `@PersistenceContext`로 주입받아 `em.persist()`와 `em.find()`를 직접 호출하는 저수준(low-level) 방식으로 저장과 조회를 구현했다. 이를 통해 스프링 데이터 JPA가 내부적으로 어떤 방식으로 EntityManager를 활용하는지 그 기반 원리를 체감할 수 있었다.

`application.yml` 설정을 통해서는 H2 데이터베이스에 접속하는 방법과, `ddl-auto: create` 옵션으로 애플리케이션 실행 시마다 스키마를 새로 생성하도록 하는 방법을 익혔다. 또한 `hibernate.SQL` 로그 레벨을 debug로 설정하고 `format_sql: true`를 함께 켜서, 하이버네이트가 실제로 어떤 SQL을 생성해 실행하는지 콘솔에서 보기 좋게 확인하는 방법도 학습했다.

마지막으로 `MemberRepositoryTest`에서는 `@SpringBootTest`와 `@Transactional`, `@Rollback(false)`를 함께 사용해 테스트에서 저장한 데이터가 실제로 DB에 반영되는지 확인하는 방식을 실습했다. 특히 인상 깊었던 부분은 저장 직후 같은 트랜잭션 안에서 `find()`로 다시 조회한 엔티티가 저장할 때 사용했던 엔티티 객체와 `==` 수준에서 동일하다는 점이었는데, 이는 영속성 컨텍스트(1차 캐시)가 같은 트랜잭션 내에서 동일한 식별자로 조회하면 항상 같은 객체를 반환해 엔티티의 동일성을 보장해주기 때문이라는 것을 이해할 수 있었다.
