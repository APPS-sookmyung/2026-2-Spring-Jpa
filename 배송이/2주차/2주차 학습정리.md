# Spring JPA 2주차 - JPA 기초

**스터디 날짜: 2026년 9월 23일**

## 1. JPA

JPA(Java Persistence API)는 **자바 객체와 관계형 DB를 매핑하기 위한 표준
API**이다. 애노테이션을 통해 객체와 테이블의 관계를 설정하며, 실제
프로젝트에서는 주로 Spring과 함께 사용한다.

### 주요 특징

-   애노테이션 기반 객체-테이블 매핑
-   `String`, `int`, `LocalDate` 등 기본 타입 지원
-   커스텀 타입 및 값 객체 매핑
-   1:1, 1:N, N:1, N:M 등의 연관관계 지원
-   상속 구조 매핑 지원

## 2. 기본 구조와 영속성 컨텍스트

JPA는 `EntityManagerFactory`를 초기화한 뒤 `EntityManager`를 생성하여 DB
작업을 수행한다. 데이터 변경은 트랜잭션 안에서 이루어지며, 사용이 끝나면
자원을 반환한다.

Spring과 함께 사용할 경우 이러한 과정의 대부분을 Spring이 관리해주기
때문에 개발자는 매핑 설정과 비즈니스 로직에 집중할 수 있다.

**영속성 컨텍스트**는 엔티티를 관리하는 공간이다. 영속 상태의 엔티티가
변경되면 JPA가 이를 추적하고, 트랜잭션 커밋 시점에 변경 내용을 DB에
반영한다.

## 3. 엔티티 CRUD

`EntityManager`가 제공하는 메서드를 이용해 엔티티 단위로 CRUD 작업을
수행한다.

-   `persist()` : 엔티티 저장
-   `find()` : 엔티티 조회
-   엔티티 값 변경 : 수정
-   `remove()` : 엔티티 삭제
-   `merge()` : 엔티티의 상태를 영속 엔티티에 병합

`find()`를 사용할 때는 엔티티의 식별자 타입과 전달하는 ID의 타입이
일치해야 한다.

## 4. 엔티티 매핑

-   `@Entity` : JPA가 관리할 엔티티 클래스 지정
-   `@Table` : 매핑할 테이블 지정
-   `@Id` : 엔티티의 식별자 지정
-   `@Column` : 매핑할 컬럼 지정
-   `@Enumerated` : enum 타입 매핑

`@Entity`와 `@Id`는 엔티티를 구성하기 위해 필수적으로 사용한다.

## 5. 식별자 생성 방식

1.  **직접 할당** : 저장 전에 개발자가 직접 식별자 설정
2.  **IDENTITY** : DB의 `AUTO_INCREMENT` 등을 이용해 식별자 생성
3.  **SEQUENCE** : DB 시퀀스를 이용해 생성
4.  **TABLE** : 별도의 테이블을 이용해 식별자 생성

``` java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

## 6. @Embeddable

`@Embeddable`은 여러 필드를 **하나의 값 객체로 묶어 매핑**할 때
사용한다.

``` java
@Embeddable
public class Address {
    private String city;
    private String street;
    private String zipcode;
}
```

같은 `@Embeddable` 타입을 여러 번 사용해 컬럼명이 겹치는 경우
`@AttributeOverride`를 이용해 매핑 정보를 재정의할 수 있다.

## 7. @SecondaryTable

`@SecondaryTable`은 **하나의 엔티티를 여러 테이블에 매핑할 때**
사용한다.

다른 테이블에 저장된 데이터도 하나의 엔티티에서 함께 관리할 수 있으며,
다른 테이블의 데이터가 하나의 값 객체로 볼 수 있는 경우 `@Embeddable`과
함께 사용할 수도 있다.

## 정리

이번 주차에서는 JPA의 기본 구조와 영속성 컨텍스트, CRUD 처리 방법을
학습했다. 또한 애노테이션을 통한 엔티티 매핑과 식별자 생성 전략을
살펴보고, `@Embeddable`과 `@SecondaryTable`을 이용해 값 객체와 여러
테이블을 매핑하는 방법을 공부했다.
